# Почему так устроено

| Решение | Что решает | Цена / когда менять |
| --- | --- | --- |
| SQLite и стандартная библиотека | Транзакции и повторный запуск без установки сервера | Один писатель; для нескольких хостов нужен другой транспорт |
| BEGIN IMMEDIATE до SELECT | Сериализует выбор и изменение готового сообщения | Короткое ожидание блокировки; timeout 5 секунд, автоматического SQL retry нет |
| Отдельные claim и apply | Выдача переживает смерть worker, срок разрешает повтор | Между шагами возможна повторная доставка |
| generation при каждой выдаче | Старый worker не завершит новую выдачу того же ID | Проверка нужна во всех завершающих операциях, включая fail и redrive |
| Эффект и ACK в одной транзакции | Сбой не оставляет принятую сумму без подтверждения | Работает только для результата в той же SQLite |
| Неизменный payload event_id | Повтор не скрывает исправленное содержимое | Исправление данных требует нового события |
| Три попытки и DLQ | Ошибка не повторяется бесконечно | Сроки и лимит требуют наблюдения, ручного решения |
| Ручной redrive | Вернуть сообщения после устранения причины | Не исправляет payload; повторно плохие данные снова станут dead |
| Обычный rollback journal | Для коротких локальных транзакций достаточно штатного режима | Нет цели оптимизировать нагрузку, длительные чтения могут задерживать писателя |
| Модельное время demo | Детерминированно проверяет границы без sleep | Обычный CLI использует системные секунды; часы хоста должны быть корректны |
| Нулевые зависимости | Быстрый запуск и простая поддержка | SQLite входит в Python/ОС и проверяется по фактической версии |

Состояние leased не доказывает, что worker жив. Это ограниченное по времени право
на завершение. generation — номер выдачи, не секрет и не средство аутентификации.
Очередь является библиотекой локального доверенного процесса, не защищённым сервером.
Поэтому обход через произвольный SQL владельца файла не входит в гарантии приложения.
